# 需求:任务类型与推送策略

> 本文档只记录**需求**(用户 2026-07-27 的原始思考),不写具体技术方案/表结构。
> 方案在需求确认后另行设计。

## 一、任务层:事情列表分几类

### 1. 周期性任务
- 例:每天打原神每日、每周打周本、每月看 SpaceX 频道的每月全球航天发射汇总、每年看各领域年度总结/年度报告。
- 周期**可自定义**(日/周/月/年…)。
- 与下面 ddl / start 任务的区别:**一次完成后不会消失,下次会再次启动,直到被关闭**。

### 2. DDL 任务
- 例:某日交付项目。
- 截止时间是**写死的,改不了**。
- 随着时间越近,越紧张。

### 3. 启动时间任务
- 与 DDL 相反,由**启动时间**驱动,没有截止日期。
- 越久没做,越要增加重要性。
- 例:很久不见的朋友、家人;体检;旅游;好几年没看生物技术发展了可以去看看……**任何"觉得我好久没做了"的事情,都可归为这类**。

### 4. 不限时、随时可以做的
- 例:突发奇想给自己开发某个软件。
- 持续很久不做、忘了也没啥;没有 ddl 也没有周期。

> **待讨论**:第 4 类本质上可能就是第 3 类——一个想法出现的那一刻,就相当于有了一个"启动时间"。若成立,可**去掉第 4 类,降低维护成本**。

## 二、任务打 tag

- 任务可以打 tag,用于**筛选 / 过滤**。
- 动机:避免"心血来潮把原神加了 10 个任务,导致其他任务找不到"——可以用 tag 筛出或隐藏某一类(如所有原神任务)。

## 三、推送层(与任务层独立)

- 任务层与推送层**相互独立**。
- 推送层记录:**每次推送时间**、**每次推送后是否完成**。

### 各类任务的推送策略

1. **周期性任务**:随临近周期末尾增加推送频率。
   - 每日任务:越临近夜里,频率越高。
   - 每周任务:越到周末,频率越高。
   - 月度、年度同理。

2. **DDL 任务**:随临近日期,增加推送频率。

3. **启动时间任务**:很随意,**间隔逐渐拉长**。
   - 例:某任务上次推送是 10 天前,没完成,于是过 10 天再问;还没在意,下次可能过 20 天再问——类似**指数增长(的间隔)**。

4. **不限时任务**:可参考第 3 类(启动时间)。
   - 因为不限时任务本质就是启动时间任务:想法一出现,就相当于出现了一个启动时间。
   - (若第 4 类并入第 3 类,推送策略也随之统一。)
