# 节律四态(V4.2 语义)

> 组成架构见 [architecture.excalidraw](architecture.excalidraw),选型依据见 [community-survey.md](community-survey.md)。
> V4.2 后节律不再需要自建状态机:**四态是 cron 任务密度的差异,不是另一个组件。**

## 四态定义(V4.2 平移)

| 状态 | 含义 | 实现 |
|---|---|---|
| **休眠** | 程序关机 | 退出 dsh-desktop。错过的闹钟由 dsh-cron 重启后"合并为最新一次"补课 |
| **睡眠** | 大脑停止,宿主活着 | dsh-desktop 托盘常驻;coldWake 关闭,cron 只走表不唤醒 |
| **待机** | 低 Token 唤醒 | coldWake 开;cron 里只有低频任务(每小时几次基本回顾) |
| **工作** | 高频观察 | cron 任务密度调高;主动观察靠**结构化信号**(DSH 会话状态标记),不做屏幕监视 |

## 唤醒经济学(仍然成立)

缓存命中 ¥0.02/M 下,一次十分之一窗口的唤醒 ≈ ¥0.002;待机 100 次/天 ≈ ¥0.2,放宽 5 倍 ≈ ¥1/天。可接受,不做无谓优化。

## 磨合机制(自 V3 保留,机制不变)

- **换档带防抖**:最小驻留 + 日换档上限 + 每次换档带理由进日志——落到女仆对 cron 任务的调整行为上
- **作息先验**:星期×小时 → 档位,周统计学习;AI 只在证据强时偏离
- **shadow mode**:前期女仆的换档决定只记日志对照,一致率达标后放开
- 人格变量(可爱/严肃/好感度)存 SQLite 档案,由任务完成情况驱动——社区确认这是空白,纯自建

## 设计宪法(两次架构翻转都活着的原则)

1. **闹钟就是闹钟,女仆才是决策者**——dsh-cron 只管到点响;看时间、看主人、看环境、重排闹钟全是女仆醒来的事
2. **先定基本方向,未来慢慢调整**——反过度设计;实现层已死过三次(V4 daemon → V4.1 意识层 → V4.2 社区组装),原则零改动
