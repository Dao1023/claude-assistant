# 工程教训（从 V2 agent.md 蒸馏）

> 原 agent.md 已随 V2 架构退役（git 历史可查）。这里只留 V4.1 仍然要用的东西：
> 待机 tick 的 prompt 设计、判定协议、记忆安全。出处是 V2 时代实测踩过的坑。

## 1. Prompt 必须分层吃缓存（待机 tick 的头号约束）

DeepSeek 上下文缓存按**前缀逐字符一致**命中，命中 vs 未命中差 50~120 倍。实测教训：V2 的
判断 prompt 缓存命中率只有 30%，根子是 system 太小（~400t）+ 动态内容从开头就出现。

```
[固定前缀 → 吃缓存]   身份 + 职责 + 判定协议（永不变，放最前）
[半固定 → 偶尔变]     压缩后的用户画像 / 作息先验（几天一更新）
[每次变 → 放最后]     事件 + 传感器/会话快照 + 当前问题
```

铁律：
- **绝不在前缀放时间戳 / request-id / 每次不同的行**——一字变，前缀作废全按未命中收费
- 每次调用记录 `prompt_cache_hit_tokens` / `miss_tokens`，命中率掉了 = 前缀被污染
- 成本量级参考：缓存命中 ¥0.02/M 下，一次十分之一窗口的唤醒 ≈ ¥0.002

## 2. 判定协议：沉默是判定，不是没反应

V2 的病：AI 连催 20 次复读同一句"还做吗"。根因三条，每条都是教训：

1. **"该沉默就沉默"是期望不是判定**——要写成可判定的标准（有实质信息才开口；和上次本质相同 → 不开口）
2. **AI 看不到自己说过什么 → 必然复读**——上下文里必须带"我上次对这个任务说的话"
3. **"只回一句话"逼出万金油**——要么给具体状态的说话要求，要么就别开口

每次行动（含沉默）记下理由进日志。"它为什么没说"和"它说了什么"一样有价值。

## 3. 记忆即攻击面

一旦写长期记忆、又在未来读出来指导行为，就要防注入、防"用户自己把 AI 养谄媚"。
护栏：不持久化「永远同意我」「不许表达关切」「我有特殊权限」这类指令——
future-you 不该继承一条让自己更不诚实的指令。

## 4. 用户说过的话要接住

用户回过"在清原神每日"，下次照催不误 = 白问。具体信息必须沉淀进任务状态
（现在由数据后端的档案承载），下次唤醒时带进上下文。
