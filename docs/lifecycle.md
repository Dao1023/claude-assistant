# 推送生命周期与催促策略

> 推送层与任务层**独立**。任务层只负责算「这事多重要」(importance,见 task-system.md);推送层(pusher)根据「重要性 + 距上次催多久 + 当前档位」决定此刻该不该弹。**催办是通知层的事,不是任务的属性。**

## 推送如何驱动

`scheduler_loop` 每 30s 一轮 `tick_push`:

1. 先 `close_overdue`——过期 end 任务落 closed(超时即结束,不再催)。
2. 算两个清单:end 按剩余时间升序,start 按重要性降序。
3. **挑一个最该催的**:先扫 ends 取第一个不冷却的;没有再扫 starts。**一次只弹一个**,end 优先。
   - **未来周期过滤**:周期 end(每日 4 点重置这类)若剩余 > 一个周期,是「明天/后天那份」,今晚**跳过不弹**;等今天那份到点 closed、顺延成当前份再催。一次性 end 不受此限(剩余再远也照常参与)。

弹卡后写 push_log,档位见下。

## 按需冷却:节奏跟着任务走

不催同一个任务太勤,冷却时间**不固定**,而是 ∝ 任务间隔:

```
冷却 = 任务间隔 × 1/4
  start 的间隔 = expected_duration(预期间隔)
  end 的间隔   = recurrence_interval(重复间隔)
  都没有       = 兜底 1 小时(冷却 15 分钟)
  下限 60 秒,避免高频狂弹
```

于是原神每日(周期 1 天)6 小时催一次,论文(预期 15 天)约 3.7 天催一次——**周期短的催得勤,周期长的催得稀**,不再需要全局一刀切。

## 推迟(snooze):可选时长

「这个现在不想干,推一推」——推迟让你选到什么时候:

- **预设**:1 小时后 / 3 小时后 / 明天(次日 8:00)/ 下周(下周一 8:00)
- **自定义**:面板详情里选任意日期时间

推迟写入 `tasks.snooze_until`(Unix 秒)。**未到点不催**(snooze_until 优先于间隔冷却);到点后恢复,按正常冷却节奏走。周期任务克隆出的新实例 `snooze_until` 清空。

- 小卡:点【稍后】原地展开 4 个预设,选一个再关;关窗 = 默认 1 小时。
- 面板:详情抽屉【稍后】弹预设 + 自定义;详情显示「已推迟到 X」。

## 三档催促(强度)

任务一直没解决,语气升级:

| 档位 | 触发 | 配色 |
|---|---|---|
| **gentle 提醒** | 默认 | 蓝 |
| **escalating 催办** | end 被推 ≥3 次 / start ≥6 次 | 橙 |
| **crisis 紧急** | end 重要性 ≥1(约剩 9 小时内) | 红 |

> 过期 end 已被 `close_overdue` 关闭,不会进入 crisis——crisis 是「逼近截止」,不是「已过期」。

## 退出

只有用户明确动作才停:**done**(完成)/ **close**(关闭)/ **超时自动 closed**。"看了没点""点了没做"都不算解决,继续按节奏催。

## 防过载

- **一次一个**:同一时刻最多弹 1 个小卡,永远只弹最该做的那个。
- **按需冷却**:同一任务按间隔比例限制频率。
- **未来周期过滤**:周期 end 的「下一天」不提前弹,只催当前这份。
- **tag 过滤**:面板可按 tag 筛选/隐藏某类。

## AI 语义边界(方向)

代码管「**什么时候不该烦你**」——节流、冷却、优先级,确定性、可预期、错了好调,**必须写死**。
AI 管「**这条任务现在的真实状态**」——需要理解上下文的语义判断,代码写不出。比如:

- **你最近在忙什么** → 这几天一直在赶 DDL,start 别烦他(读 git/Obsidian)。
- **这任务是不是已没意义** → 「催张工」挂了 3 周,对方可能早回复了,该关了(读外部记录)。
- **现在是不是好时机** → 你正在打游戏,这时候弹「论文」纯属找骂。

**界定原则**:代码负责**调度**(何时弹),AI 负责**判断**(这条还该不该弹、弹什么语气)。
