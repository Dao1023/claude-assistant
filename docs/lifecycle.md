# 推送生命周期与催促策略

> 推送层与任务层**独立**。本文描述推送如何驱动、每个任务的推送生命周期、催促节奏与防过载。

## 推送层如何驱动

推送层定时扫描"今天要干什么",产出两个清单:

- **end 清单**:按结束时间排序(最近的在前)。
- **start 清单**:按**重要性算法**排序(`log(发生以来/正常周期)`,见 task-system.md)——不是纯按时长,否则长周期任务霸榜。

## 推送生命周期挂在任务上

关键原则:**推送是任务的属性,跟着任务走,不是独立事件流。**

- 每个任务记录自己的推送状态:被推过几次、当前频率、用户历次响应。
- 一个任务推了很久没解决 → **增加这同一个任务的推送频率**,而不是换成别的任务。
- 周期任务**克隆出新任务时,推送计数重置**(新任务还没被催过)。

## 催促节奏(三档强度)

任务不解决就一直追,有节奏、有强度变化:

| 档位 | 触发 | 行为 |
|---|---|---|
| **温和** | 到点提醒后未解决 | 随机间隔再催(如 1-3 小时随机一次),保持存在感但不烦 |
| **升级** | 逾期/被推次数累积 | 间隔逐渐缩短,频率上升 |
| **危机** | 逼近 deadline(end)或拖太久(start) | **夺命连环催**:一次连发 5-10 个弹窗 |

**退出**:只有用户明确标记 `done` / `snoozed`(稍后)/ `dismissed`(不做了)才停。"看了没点""点了没做"都不算解决。

> 注:start 任务"越久越重要"是**任务层**的 log 增长;"推了很久增加频率"是**推送层**的催收。两者叠加但独立:重要性决定它排多前,推送生命周期决定它催多勤。

## 防过载节流

任务多了会"催死用户",必须节流:

1. **同时催促上限**:同一时刻最多催 N 个(建议 3),其余按重要性排队。
2. **重要性排序**:只有当前最该催的 N 个占用弹窗名额。
3. **tag 过滤**:可按 tag 隐藏某类(如暂时不看原神任务)。
4. **全局静音**:用户可一键"今天别催了"。

## 待拍板参数

1. 同时最多催几个?(建议 3)
2. 危机连环催一次连发几个?(5-10)
3. 温和 → 危机的升级标准?(按逾期时间 / 按被推次数)
4. 温和期随机间隔范围?(建议 1-3 小时)
