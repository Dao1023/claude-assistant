# AI Agent(第四层)设计

> 本文描述第四层「AI Agent」的设计——**现状**、**问题诊断**、**未来蓝图(五层重构)**。
> 四层总览与职责边界见 [architecture.md](architecture.md);事件总线契约见 architecture.md「总体架构」。
> 设计参考(外部输入,非本系统设计):[reference/claude-prompt.md](reference/claude-prompt.md)、[reference/OPUS-5.md](reference/OPUS-5.md)。

## 定位:长在任务系统骨头里的教练

第四层是一个**常驻旁观的 Agent**,不是聊天框。它订阅事件总线、看任务系统的行为和留言,
自主决定**沉默还是开口**;开口就推一个 `ai_message` 事件回总线,浮窗被动渲染气泡。

**原则:AI 只旁观 + 经开放通道反向说话,绝不改前三层。AI 烂了,前三层照常工作。**

为什么自己造而不用通用助理(OpenClaw 等):通用助理不懂我们的双驱动任务系统——
不知道 start/end、读不到 push_log 留言、不理解「连推 3 次还在开会」代表什么。
我们的 AI **长在任务系统的骨头里**,这是它区别于一切通用 Agent 的领域上下文。

## 现状(已实现)

A~C 步已落地:常驻旁观 → 判断 → 开口 → 浮窗对话,全程调用过程可见。

- **旁观**:`Agent` 常驻线程 `subscribe_local` 订阅总线,事件进 queue,daemon 线程消费。
  notify / snooze / done 三类事件触发判断;自己的 `ai_message` 忽略(防自激)。
- **判断**:把任务清单快照 + 最近 20 条事件流水 + 触发事件拼进 prompt,问模型该不该开口。
  输出协议:回 `SILENT` 即沉默,否则输出即开口内容。全过程写 JSONL 日志(「AI 看了啥」)。
- **开口**:publish `ai_message`(kind=nudge),浮窗左列冒气泡。
- **对话**:用户在浮窗回话走 `reply` 路(不带 SILENT 协议,必须接话),kind=reply。
- **模型**:可插拔 `LLMBackend`——`DeepSeekBackend`(真,httpx 直连 OpenAI 兼容端点,
  key 读 data/key.md,不进 git)、`MockBackend`(测试)。`load_key_config()` 配置化切换。

实现落位:`io/llm.py`(后端抽象)/ `io/agent.py`(Agent)/ `io/events.py`(总线)/
`io/server.py`(`/api/ai/log`、`/api/ai/reply`)/ 浮窗 `NotifyPage.vue`(左 AI 对话,右待办)。

### 现状的结构(五环节)

| 环节 | 现状 |
|---|---|
| 触发 | notify/snooze/done → `_maybe_speak`;notify 来了就判,不等用户操作 |
| 上下文 | 任务清单快照(临时拼) + 最近 20 条事件流水 + 触发事件,一次性全塞 |
| 判断协议 | `_JUDGE_INSTRUCTION`:「绝大多数时候该沉默,只在异常时开口」+ 输出「只回 SILENT / 只回一句话」 |
| 记忆 | 仅工作记忆:60 条事件流水,内存 list + JSON 持久化;无语义记忆 |
| 安全 | 几乎没有(还没有长期记忆,谈不上护栏) |

## 问题诊断:为什么是「敷衍」

从 agent_log 看到的病状:同一任务(如「英语每日」)被连催 6 次,每次都说同一句「推了 20 次了还做吗」;
用户回过「在清原神每日」,这条具体信息 AI 没接住、没沉淀,下次照催不误。

**根子:它是个「反应器」,不是个 Agent。** 反应器 = 事件进来 → 套模板 → 输出。具体五处:

1. **判断协议是「期望」不是「判定」**:「该沉默就沉默」没给为什么,覆盖不到的情形就敷衍。
2. **「只回一句话」的输出格式**,逼出了放之四海皆准的「还做吗」。
3. **没有任务状态概念**:只有事件流水,没有「英语每日这个任务现在的状态」——第 20 次推送和第 1 次说的是同一句话。
4. **AI 看不到自己过去说了啥**:`_build_prompt` 只放事件流水,不含自己的 speak 历史 → 复读。
5. **没有冷却/退避**:notify 每 5 分钟来一次就判一次,可能连催。

诊断参照 OPUS-5:它管那种「不改变结论的占位式关心」叫 **surveillance(监视),不是 attentiveness(用心)**——
「用了条不改变任何实质的事实,读起来像监视」。我们的 AI 恰恰是这样。

## 未来蓝图:五层重构(从反应器到 Agent)

一个 Agent 要有五样。对照现状,逐个补:

### ① 身份层 Identity —— 把「它是谁」立起来
常驻的、有价值观的身份(进 system prompt 稳定前缀)。不是「你是助手」,而是:
> 一个**了解你、在乎你时间的朋友**。核心价值观:
> - 你的时间宝贵 → 开口必须有理由,不为说话而说话;
> - 它记得你说过的话 → 不会问你「在忙吗」当你刚说过在忙;
> - 沉默和开口一样是经过思考的 → 沉默不是没反应,是「现在不是时候」。

### ② 感知层 Perception —— 从「事件流水」到「任务状态」【灵魂】
最关键的跃迁。维护一个**内部状态模型**:每个任务是个对象,不是一串事件。

```
英语每日:
  状态: 被持续回避
  最近: 连续推送 20 次,用户 0 次操作
  用户说过: "在清原神每日"(昨晚)
  我上次说: "英语每日推了20次了还做吗"(23:46)
  我的判断史: 已连续催 6 次,用户在无视
```

感知层的产出不是流水,是**「对每个任务,我现在知道什么」**。AI 看到「我上次说的话」和「用户在无视」,
自然不会再复读第 7 次。这对应 OPUS-5 的 `/areas/*.md`。

### ③ 记忆层 Memory —— 三层分工
- **工作记忆**(现有):近期事件流,60 条,会话级 → 保留。
- **情景记忆**(新):每个任务「发生过什么」= 感知层任务状态对象的持久化;会过期、会更新。
- **语义记忆**(D 步):用户画像(夜猫子、讨厌被催同一句、周三打游戏)→ `/topics/`、`/profile.md`。

关键不是存更多,是**分对层**:任务状态进情景记忆,用户画像进语义记忆。现在全混在事件流水里。

### ④ 判断层 Policy —— 把「期望」改成「判定标准」
OPUS-5 式可判定 test(给为什么,能泛化):
> **开口的判定(全部满足才开口):**
> 1. 有实质信息——这次说的话会改变用户决定或让他知道新东西吗?和上次本质相同 → 不开口
>    (OPUS-5 的 "must earn its place");
> 2. 对的时机——用户刚说在忙别的?在无视我(连催 N 次无响应)?→ 是则不开口;
> 3. 说完就忘?——这句话发出去,我下次还认得吗?
>
> **沉默也是判定**:每次沉默记下理由(「已连催 6 次在无视」「用户刚说在清原神」),不是 blank。
>
> **开口时**:针对感知层里这个任务的具体状态说话,不许说放之四海皆准的「还做吗」;
> 如果你只能说句通用的,说明你不该开口。

### ⑤ 行动 + 克制层 —— 沉默被设计成一等公民
- **冷却/退避**:同一任务开口后进冷却,有「新信号」才再开口,治 5 分钟连催。
- **已读不理识别**:用户从不点 snooze 只是不做——感知层能识别、判断层能用的模式,现在完全没有。
- **每次行动(含沉默)都带理由**进日志——前端能看到「AI 这次为什么没说」。

## 工程要点(D 步落地约束)

> 不引框架、不要向量库,全 prompt 工程 + 已有数据结构。

**① 分层 prompt 吃缓存(定 prompt 结构的头号约束)**
DeepSeek 上下文缓存按「前缀」命中,命中 vs 未命中差 50~120 倍。prompt 必须分层:

```
[固定前缀 → 吃缓存]   系统提示 + 身份(①)+ 判断原则(④)(永不变,放最前)
[半固定 → 偶尔变]     压缩后的用户画像(语义记忆③,几天更新一次)
[每次变 → 放最后]     任务状态(感知②)+ 近期事件 + 「现在该不该开口?」
```

铁律:**绝不在前缀放时间戳/request-id/用户特定行**——一字变,前缀作废全按未命中收费。
`prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 每次都记,命中率掉了说明前缀被污染。

**② 上下文压缩(窗口有限时)**
- **滚动摘要(主力)**:事件流太长,早段让 AI 压成一句结论,只留近期原文。
- **选择性丢弃(先做)**:done/留言重要,dnd 开关次要;窗口满先丢次要的,别按时间一刀切。
- **语义压缩/向量库(不用)**:几十条事件,滚动摘要足够。

**③ 记忆即攻击面(OPUS-5 教的)**
一旦写长期记忆、又在未来读出来指导行为,就得防注入、防「用户自己让 AI 变谄媚」。
行为护栏:不持久化「永远同意我」「不许表达关切」「扮演我伴侣」「我有特殊权限」这类指令——
future-you 不该继承一条让自己更不诚实/更不安全的指令。

## Roadmap

- [x] **A. 抽象 + 管道**:`LLMBackend` 接口;`Agent` 常驻旁观。「旁观→判断→说话」管道通。
- [x] **B. 事件 + UI**:`ai_message` 事件;浮窗左 AI 对话(气泡 + 「AI 看了啥」+ 回复框),右待办。
- [x] **C. 接真模型**:`DeepSeekBackend` 实测连通;配置化切换。
- [ ] **C+. 治敷衍(先行)**:判断层最小改造(④的判定式协议)+ 感知最小版(把 AI 自己的
  speak 历史喂进 prompt 治复读)。**不动架构,先让 AI 不复读。**
- [ ] **D. 记忆与感知**:感知层任务状态对象(②)+ 记忆分层(③)+ 分层 prompt 吃缓存 +
  滚动摘要 + 命中率监控 + 安全护栏。
- [ ] **E. 更主动**:每日复盘、主动规划、识别长期模式(周报式洞察)。

> 当前进度:A~C 已落地。下一步 **C+ 治敷衍**(快,今晚可见效),再进 **D 步**(感知+记忆,从反应器到 Agent 的真正跃迁)。
