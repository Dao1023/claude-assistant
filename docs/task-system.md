# 任务系统

> 本文描述任务模型。完整需求见 [requirements.md](requirements.md);存储选型见 [storage.md](storage.md)。

## 两类驱动方式

所有任务只有两种驱动,是一对镜像:

| | start 驱动 | end 驱动(DDL) |
|---|---|---|
| 本质 | 越久没做越重要 | 越近截止越急 |
| 增长 | 对数(缓慢) | 越近越陡 |
| 过期 | 不会"没了",只会越来越该做 | 过了就没了 |
| 例 | 看朋友、体检、旅游、关注某领域、突发奇想 | 项目交付、原神每日、火车 16:25 |

## 周期任务:start/end 的修饰符

周期不是第三类驱动,而是叠加在 start 或 end 上的属性:

- **周期 end**:原神每日、周本——到点过期,做完生成下一个。
- **周期 start**:见朋友约定再聚——做完锚点重置,生成下一个。

**实现**:任务标记"是否周期"。完成后系统**自动克隆一个一模一样的下一个任务**,除非手动彻底关闭。

## 重要性算法(log)

> **时间与周期内部一律 Unix 秒级**,start / end 都按秒算,精度统一。
> 周期天数在计算时换算成秒(`cycle_days * 86400`)。

### start:`log(距上次以来 / 正常周期)`
- `x = (now - anchor) / (周期 × 86400)`,重要性 = `log(x)`。
- `x=1`(刚到周期)→ 0,该做但不急;`x<1` → 负,不排上号;`x>1` → 缓慢上升。
- 刚建/刚做完时 `x` 是 0~1 小数,`log(x)` 是**有限负数**自然排最后——不再有 `log(0)=-inf` 的特判。
- 用"正常周期"归一化,长周期任务(体检一年)不会因"最久"霸榜。
- start 任务需要"**正常周期**"字段(预期间隔,非结束时间);`anchor` 是上次完成的时间戳,做完重置为 now。

### end:`-log(剩余时间)`
- 剩余越少值越大。剩 30 天 → -3.4;剩 1 天 → 0;剩 0.1 天 → +2.3。
- 剩余按秒差换算成天数再取 log,保持数值范围与前端逾期/着色阈值兼容。
- 已过期(剩余 ≤ 0):设为很大的固定值(`OVERDUE = 1e9`),表示"已错过,最高优先"。

## 任务的核心属性(概念层,非表结构)

- **内容**:标题、备注。
- **驱动**:start / end。
- **是否周期** + 周期参数(cycle)或正常周期(用于 start 归一化)。
- **时间**:created、deadline(end)、anchor(start 上次完成)。
- **tag**:多个,用于筛选/过滤。
- **主观优先级**:与客观重要度加权。
- **状态**:active / done / 已关闭。
